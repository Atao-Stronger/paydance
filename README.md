# 下班倒计时桌面小窗

> 当前版本 **v1.0.0** · License: MIT
>
> 一个 Windows 11 桌面常驻的超轻量小窗：**实时显示距下班还有多久、今天已经赚了多少钱**。
> 桌面小窗使用 Tkinter/Pillow，设置与日历使用 Qt（PySide6）。

功能设计参考了开源项目 [wealth-clock](https://github.com/enkarnur/wealth-clock)（MIT），但按"贴桌面的小窗"需求从零实现，更轻量。

## 界面

小窗尺寸跟随系统 DPI 自动缩放（150% 缩放的屏幕上就是 1.5 倍），
也可以在设置里用「面板大小」在 25%~100% 之间手动微调。

```
┌──────────────────────────────┐
│ 上班中               加班 20:30 │ ← 左：当前状态  右：加班日显示加班结束时间
│      ╭────────────────╮       │
│     ╱    ¥180.00      ╲       │ ← 环内金色大字：今日已赚（缓动跳动）
│    │      今日已赚       │      │
│     ╲                  ╱      │ ← 圆环＝今日进度：从 12 点顺时针，
│      ╰──────●─────────╯       │   渐变色 + 流光 + 呼吸光晕，头部跟着一颗金球
│  ┌──────────────────────┐    │
│  │   🕐  02:34:56         │    │ ← 距下班倒计时胶囊（冒号每秒呼吸）
│  └──────────────────────┘    │
└──────────────────────────────┘
```

## 动效

- **启动淡入**：小窗淡入出现，退出淡出
- **金额缓动**：今日已赚金额像秒表一样平滑跳动，不是生硬跳字
- **进度环**：渐变进度与柔和呼吸光晕；进度按真实工作时间推进，午休和可选晚休期间冻结
- **倒计时呼吸**：冒号每秒明暗呼吸，最后 1 小时整体变橙、10 分钟变红（颜色渐变过渡，不突变）
- **下班彩带**：到点下班自动撒一把彩带 🎉
- 鼠标划过和按住时画面不变，避免干扰（卡片固定方角、无悬停高亮）
- 不喜欢动效？config.json 里 `"animations": false` 一键全关

- **午休时段冻结金额**，午休不算钱
- **可选晚休**：仅在加班日生效，晚休期间金额与进度冻结，结束后继续累计
- **月收入累计**：按当月日历逐日计算；工作日、补班、休息日和加班都可在设置中调整
- **加班开关**：托盘/右键菜单勾选「今天加班」，下班时间顺延到配置的加班时间，并按“加班日总收入”计算；加班时标题显示“加班中”，右上角显示加班结束时间；该开关按天自动重置
- 下班前 1 小时倒计时变橙、最后 10 分钟变红
- 下班后状态显示"已下班"，环内改为显示**本月已赚**，撒彩带
- 未安排工作的休息日显示"今日休息"；2026 年按国务院公布的节假日与调休判断
- 上班前显示"距上班"倒计时

## 快速开始

源码运行先执行 `python -m pip install -r requirements.txt`，安装 Pillow 和 PySide6。
打包版 `下班倒计时.exe` 已自带依赖，无需安装 Python 或 Qt。

1. 双击 `启动下班倒计时.bat`（后台静默启动，无黑框）
2. 小窗默认出现在屏幕右上角，**按住左键可拖动**，位置自动记忆（多显示器下也不会跑回主屏）
3. 右键小窗，打开「个性化与工作设置」即可调整薪资、作息与外观

## 开机自启

- 双击 `设置开机自启.bat`；打包版直接登记 EXE，Windows 启动设置中显示应用名称和 logo，源码版仍使用 VBS 静默启动
- 或在**托盘/右键菜单**里勾选「开机自启」（随时可取消）
- 取消自启：右键菜单取消勾选，或在 Windows「设置 → 应用 → 启动」中关闭。已有 VBS 启动项会在打包版运行时自动迁移，并保留原来的启用/禁用状态。

## 个性化与工作设置

在小窗或托盘菜单中打开「个性化与工作设置」。Qt 设置窗口分为「收入与扣除」「作息与日历」「小窗外观」三个页面，可以选择按天发薪或按月发薪，并配置日薪/月薪、月补贴、上下班时间、午休时间、
可选晚休、加班下班时间、加班收入、工作日、主题、强调色、透明度、**面板大小**、字体大小和动效。
点击「保存」会立即生效并保留设置窗口；点击「保存并关闭」则在保存后关闭窗口。两者重启后都会保留。设置窗口独立运行，编辑时桌面小窗继续更新；底部保存按钮固定可见，窗口较小时内容可滚动。
设置窗口顶部固定显示「本月已赚」，切换页面或滚动时始终可见。金额每秒更新，包含本月已过日期的收入和今天实时已赚的部分；采用已保存的计薪与扣除设置，保存后立即刷新。
薪资设置下方会实时预览本月工作日数、正常日收入与加班当天总收入；修改金额或工作日选择时立即更新，无需先保存。

月薪模式按“（月薪＋每月固定补贴）÷ 当月应工作日数”折算每日金额；若普通工作日加班，再直接加上设置的“月薪加班额外收入/天”。日薪模式也会把每月固定补贴按当月应工作日数折算，分别加到日薪和“加班日总收入”上。

“社保与公积金扣除”可选“不扣除”“五险一金”或“六险二金”。选择后填写每月个人缴纳总额，软件按当月工作日分摊扣除，实时收入、每日预览和本月累计同步更新。月薪模式按“（月薪＋补贴－个人缴纳总额）÷ 当月工作日数”计算；日薪模式从每日收入中扣除相同的每日分摊额，加班额外收入照常计入，扣后收入最低为 0。不扣除时保留原有计算；若填写的工资已是实发金额，请选“不扣除”。日历手填金额视为最终收入，不再重复扣除。缴纳金额由用户填写，软件不预设地区或单位的缴费比例。

点击设置中的「编辑当月日历」，可以逐日修改日期类型（工作日、调休补班、普通休息日、法定节假日）、出勤状态和当天收入。金额框会预填按当前薪资算出的每日收入；休息日加班预估为普通日收入的 2 倍，法定节假日加班预估为 3 倍，均可改为实际收入。这只是软件预估，实际加班工资基数请以劳动合同和单位规则为准。金额必填、不得为负数、最多两位小数。日历会显示已过日期累计和全月预计；「全按正常」「全按加班」是工作日的初始统计方式，逐日修改优先。右键菜单在休息日会引导到日历填写加班收入。

进入新月份后，旧月份逐日记录自动清除，只保留上一月的薪资汇总；程序关闭期间跨月，会在下次启动时处理。2026 年法定节假日 13 天按[济南市人社局说明](https://www.jinan.gov.cn/col/col118356/art/2026/art_5c0f206d9dc945faa30f68f8e811be7e.html)标注；其他年份的联网数据只标明放假与补班，法定节假日类型需要在日历中手动确认。
2026 年节假日/调休依据[国务院办公厅通知](https://www.gov.cn/gongbao/2025/issue_12406/material/gwygb202532.pdf)内置。其他年份启动后会后台读取并缓存 [holiday-cn](https://github.com/NateScarlet/holiday-cn) 提供的国务院节假日数据；未发布或没有缓存时明确标注“按星期估算”。地区或单位单独的安排不包含在内。

打包版的个人配置保存在 `%APPDATA%\PayDance\config.json`，节假日缓存保存在 `%LOCALAPPDATA%\PayDance\calendar`。首次运行会迁移 EXE 旁已有的有效旧配置；分发包不应附带个人配置。源码运行仍使用项目目录的 `config.json`。应用改名后沿用这些目录，已有薪资和作息设置会保留。

## 常见问题

- **看不到小窗了？** 按 `Ctrl+Alt+D` 呼出；或托盘图标右键 → 显示/隐藏。
- **小窗被别的窗口盖住了？** 说明「置顶显示」没开：托盘图标右键勾上「置顶显示」，
  它就永远浮在最上面。
- **移动了文件夹？** 重新运行一次 `设置开机自启.bat`（自启路径会失效）。
- **彻底卸载？** 托盘菜单退出 → 删除启动文件夹里的 `下班倒计时.vbs` → 删除整个 payDance 文件夹。
- **开机后没自动出现？** 确认启动文件夹里 `下班倒计时.vbs` 存在，且本机 Python 的
  `pythonw.exe` 在 PATH 中；若 Python 安装位置变了，重跑 `设置开机自启.bat` 即可。

## 技术说明

- 主程序：`paydance.pyw`（计薪、桌面小窗、托盘、热键与自启）；`settings_ui.py` 提供 Qt 设置与日历，`settings_bridge.py` 通过本地进程管道将保存操作交回主程序。
- 无边框窗口 + 方角（已关掉 DWM 圆角）+ 半透明；托盘图标是运行时用 GDI 画的"金币¥"
- 单实例：命名互斥体，进程异常结束也会被系统自动释放，不会留下"打不开"的残留锁
- 仅在发生异常时记录日志，保存在 `%LOCALAPPDATA%\PayDance\paydance.log`；单文件最多 512KB，保留两个轮转备份并清理 14 天前的日志

## 测试

```
python -m pytest
```

测试覆盖计薪、配置兼容、桌面功能、Qt 设置、日历和进程通信。`pytest.ini` 里指定了 `--capture=sys`，这一项不能省：

测试会创建大量真实 Tk 窗口，而每次 `tkinter.Tk()` 都要重新初始化一个 Tcl
解释器并读取它自己的全部 `.tcl` 库文件。pytest **默认的 fd 级输出捕获**会把
进程的 1/2 号文件描述符换成临时文件，在这个状态下 Tcl 初始化会偶发读不到
自己的库文件，报 `TclError: Can't find a usable tk.tcl`，表现为每次跑挂 1~2 个
且失败用例每次都不同。换成 sys 级捕获后连续 17 次运行均全绿。

真实程序每次启动只建一个 Tk 解释器，从未出现该问题（25 次源码启动 +
12 次打包版启动全部成功），所以这只是测试环境特有的问题。

## 打包发行

```
python -m PyInstaller --noconfirm --clean 下班倒计时.spec
```

产物在 `dist\下班倒计时\`，**必须整个文件夹一起分发**（`下班倒计时.exe` 与 `_internal\` 缺一不可）。
spec 已按发行需要配好：onedir（启动不必解压到 `%TEMP%`，开机自启更快）、
关闭 UPX（压缩后的 EXE 是杀软/SmartScreen 误报的高发组合）。

### 关于代码签名：本项目决定不签名

未签名的 EXE 从网上下载后首次运行，Windows 会弹「Windows 已保护你的电脑」，
**点「更多信息 → 仍要运行」即可**。这是 Windows 对"不知道谁做的"下载文件的统一拦截，
不是程序本身有问题（`使用说明.txt` 里也写了这一条）。

不签名的理由：

- 签名**免除不了第一次提示**。新发布的文件即使签了名，在积累足够下载口碑之前
  仍会提示，只是窗口里显示"已验证的发布者"。口碑要靠几百次干净下载、数周时间才攒得起来。
- **EV 证书自 2024 年起不再免 SmartScreen**，行为与 OV 相同，
  仅为绕过提示而买 EV（400+ 美元/年）已无意义。
- OV 约 150~300 美元/年，且自 2023 年 6 月起私钥必须存放在硬件 U 盾或云 HSM 中。
- 微软的 Azure Artifact Signing（约 9.99 美元/月）个人开发者只开放美国和加拿大。
- 自签名证书完全无效，Windows 默认不信任。

结论：桌面小工具、分发给少数人使用，让每人第一次点一下「仍要运行」成本最低。
依据见微软 [SmartScreen 声誉](https://learn.microsoft.com/zh-cn/windows/apps/package-and-deploy/smartscreen-reputation) 与
[代码签名选项](https://learn.microsoft.com/zh-cn/windows/apps/package-and-deploy/code-signing-options)。

将来若改变主意：在 spec 的 `EXE(...)` 里填 `codesign_identity`，或对产物执行
`signtool sign /fd sha256 /tr <时间戳服务器> /td sha256 下班倒计时.exe`。
项目若开源，[SignPath Foundation](https://signpath.io) 可为符合条件的开源项目免费签名。
